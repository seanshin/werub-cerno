## 1. 요약 (Executive Summary)

Cerno는 각 의료진의 **지식·관점·설명 방식**을 반영한 개인화 임상 AI를, 환자 데이터를 병원 밖으로
내보내지 않는 **온프레미스(open-weight)** 환경에서 운영하는 시스템이다. 범용 대형 모델이 "평균적인"
답을 주는 것과 달리, Cerno는 **공유 베이스 모델 하나**에 의료진별 **경량 어댑터(LoRA)** 와 계층형 지식
저장소(**Cerno Library**)를 결합해, 각 의료진에게 "자신의 방식으로, 근거를 갖춰" 답하는 보조 도구를
제공한다.

세 기둥은 **안전(근거 기반·환각 억제)**, **주권(데이터가 병원을 떠나지 않음)**, **출처(모든 답에
근거·출처 표기)** 이다. 여기에 의료진이 올리는 지식을 **개인 자료와 출처 있는 공용 논문으로 분리
관리**하고, 의료영상·진료과별 상병 등 **다양한 도메인을 지속적으로 검토·반영**하는 구조를 갖춘다.

---

## 2. 문제의식

임상 현장에서 범용 LLM을 그대로 쓰기 어려운 이유는 세 가지다. 첫째 **데이터 주권** — 환자 데이터를
외부 API로 보낼 수 없는 규제·보안 환경이 많다. 둘째 **환각** — 근거 없이 그럴듯한 답을 내는 특성은
임상에서 치명적이다. 셋째 **획일성** — 같은 질문에도 의료진마다 강조점·접근 순서·설명 방식이 다른데
범용 모델은 이 개인차를 담지 못한다. Cerno는 이 셋을 각각 온프레미스 오픈웨이트, 근거 기반 RAG,
의료진 개인화로 푼다.

---

## 3. 접근 방식 — 하이브리드

Cerno는 "지식을 모델에 굽는" 방식과 "지식을 검색으로 붙이는" 방식을 구분한다.

- **지식(무엇을 아는가)** 은 모델 가중치에 굽지 않고 **RAG로 검색**해 근거·출처와 함께 제시한다.
  지식은 자주 바뀌고, 출처가 중요하며, 환각을 억제해야 하기 때문이다.
- **스타일·추론(어떻게 설명하는가)** 만 **LoRA 어댑터로 개인화**한다. 프론티어 모델로 각 의료진의
  추론 흐름·설명 방식을 반영한 학습데이터를 증류(distillation)해 미세조정한다.

이 분리가 안전과 개인화를 동시에 달성하는 핵심이다.

## 4. 시스템 아키텍처

```
        ┌──────────────────── 온프레미스(병원 내부) ────────────────────┐
  질문 →│  안전 사전평가 → 근거 검색(Cerno Library + EMR) → 근거충분성  │
        │        → 프롬프트 구성 → 베이스 모델 + 의료진 LoRA 생성          │→ 답변 + 출처
        │        → 가드레일 후검증(근거 없으면 회피, 고위험 검토)           │
        │                                                              │
        │  [서빙] 베이스 모델(4bit) + 의료진 어댑터 핫스왑                 │
        │  [지식] Cerno Library: 개인/그룹/공용 계층 컬렉션 + 도메인 태그  │
        │  [연동] EMR 실시간 조회(환자 맥락) · 관리 포털(문서 지식)         │
        │  [운영] 리서치 레이더(도메인 지속 검토·반영)                     │
        └──────────────────────────────────────────────────────────┘

  (오프라인·주기) 프론티어 모델 → 합성 학습데이터 → LoRA 학습(의료진 어댑터)
  ※ 약관·법무 게이트 통과 데이터만, 환자 실데이터 미포함
```

구성 요소는 공유 **베이스 모델**(7~8B, 단일 GPU 4bit 서빙; 후보 Meditron·MedGemma·Qwen/Llama·
OpenBioLLM), 의료진별 **LoRA 어댑터**, 계층형 지식 저장소 **Cerno Library**, **EMR 연동**, **관리 포털**,
그리고 도메인 지속 검토를 담당하는 **리서치 레이더**다. 두 축으로 나뉜다 — 실제 질의응답이 일어나는
**런타임 축**(베이스+어댑터+RAG)과, 지식 인제스션·개인화 학습·도메인 검토가 돌아가는 **구축 축**(주기적).

### 4.1 EMR 연동 원칙 — 별도 개발 + FHIR 느슨한 결합 (설계 결정)

Cerno는 EMR에 융합하지 않고 **독립적으로 개발·배포되는 별도 시스템**으로 두고, EMR과는 표준 **FHIR**
API로만 연동한다(원내 FHIR 연동 준비 완료). 근거는 네 가지다: (1) **규제 범위 분리** — AI의 의료기기성과
EMR 인증을 얽지 않는다, (2) **개선 주기 분리** — 자주 고치는 AI를 EMR 릴리스 주기에 묶지 않는다,
(3) **인프라 분리** — GPU 서빙과 EMR 인프라를 분리한다, (4) **데이터 경계** — Cerno는 FHIR로 조회만 하고
PHI를 저장하지 않는다. 대신 **의료진 경험은 SMART on FHIR로 EMR 화면에 임베드**해, "시스템은 분리,
경험은 통합"을 달성한다. 연동은 세 갈래뿐이다 — FHIR read(환자·진료 맥락), SMART launch(의료진·환자
컨텍스트), 선택적 SMART App Launch(화면 임베드). Cerno를 EMR 데이터스토어·시스템에 융합하지 않는다.

## 5. Cerno Library — 계층형 지식 관리

의료진이 올리는 문서는 성격이 다르므로 **3단계 공개범위(visibility)** 로 분리 관리하고, 각 계층은 별도
벡터 컬렉션으로 **물리적으로 분리**되어 독립적으로 적재·갱신·삭제·감사된다.

| 계층 | visibility | 컬렉션 | 격리 | 대표 자료 | 출처 요건 |
|------|-----------|--------|------|-----------|-----------|
| 개인 서고 | `private` | `cerno_priv` | 컬렉션 분리 + `owner` 메타(본인만) | 개인 연구·미발표·노트 | 내부 |
| 그룹 서가 | `group` | `cerno_grp` | 컬렉션 분리 + `group` 메타 | 부서 공유 자료 | 선택 |
| 공용 서고 | `org` | `cerno_org` | 컬렉션 분리(기관 전체) | 발표 논문·가이드라인 | **출처·저작권 필수** |

> **v1.1 정정.** 초판의 의료진별 컬렉션(`priv__{id}`)을 **공개범위별 3개 고정**으로 바꿨다.
> AI 서버 `/api/rag/search`가 단일 컬렉션만 받아 의료진별로 쪼개면 인원에 비례해 검색 호출이
> 늘고, 그만큼 동시 슬롯과 rate limit을 더 먹는다. 3개 고정이면 검색 호출이 **인원과 무관하게
> 항상 3회**다. private을 별도 컬렉션에 두는 것은 유지한다 — 최악 시나리오가 타 의료진 private
> 노출이므로, 물리 분리해 두면 필터 버그의 피해가 org/group 오혼입으로 제한된다.

**메타데이터(매니페스트).** 문서마다 YAML로 공개범위·출처(provenance)·저작권·도메인을 선언한다.

```yaml
doc_id, title, visibility(private|group|org), source_type,
files[], owner_clinician_id, groups[],
source: { authors[], publication, year, doi, url, license },
phi_reviewed(bool), license_approved(bool),
specialty, modalities[], icd_codes[]        # 도메인 태그(6장)
```

**거버넌스(적재 규칙).** 하나라도 어기면 적재되지 않는다: 모든 문서 `phi_reviewed=true`(비식별화);
공용(org)은 출처(doi/url/publication) + `license_approved=true`; 발표논문은 저작권 검토 필수;
private/group은 소유·그룹 정합성. 발표 논문 원문 적재는 저작권 이슈가 있어 공용 서고는 라이선스가
허용하는 자료로 한정한다.

**검색·인용.** 의료진 C의 질의는 접근 가능한 컬렉션 `[priv__C] + [grp__g...] + [org__public]` 을 함께
검색하고, 답변은 근거의 **공개범위·출처를 구분해 인용**한다(개인 자료는 비공개 출처로 라벨, 공용 논문은
저자·게재지·DOI 표기). 근거가 부족하면 생성하지 않고 "근거로 확인되지 않음"으로 응답한다.

**관리 포털.** 의료진은 EMR과 분리된 **별도 포털**에서 파일을 올리고 공개범위·자료유형·출처·도메인을
지정한다. 매니페스트가 자동 생성·검증되고, "지식베이스 적재"로 계층 컬렉션에 반영된다.

## 6. 도메인 커버리지 & 지속 검토 구조

의료영상·진료과별 상병 등 다양한 영역을 일회성이 아니라 **지속적으로 검토·반영**한다.

**택소노미(사전 구분).** 지식·모델을 세 축으로 태깅한다.

- **진료과(Specialty):** 순환기·소화기·호흡기·내분비·신장·혈액종양·감염·신경·외과·정형·산부인과·
  소아·정신·응급·영상의학·병리·진단검사·피부·안과·이비인후·비뇨·가정의학 등.
- **모달리티(Modality):** text · xray · ct · mri · us · pet · pathology · endoscopy · fundus · ecg · lab.
- **상병(Condition):** KCD/ICD-10 코드(예: I21 급성심근경색, E11 2형당뇨).

검색 시 진료과·모달리티로 **필터링**해 근거를 정밀화한다. 계층(개인/그룹/공용)과 도메인은 직교한다.

**리서치 레이더(지속 검토 파이프라인).** ① 소스 모니터링(arXiv·PubMed·Hugging Face·GitHub·학회
가이드라인·규제) → ② 트리아지(도메인 태깅·관련성·라이선스) → ③ 평가(벤치마크·임상·안전·저작권·PHI)
→ ④ 반영(지식은 Library, 모델·모달리티는 로드맵) → ⑤ 버전·감사(도메인 상태 갱신·리뷰 로그).
도메인마다 **오너**와 **검토 주기**를 두고, 레이더를 정기 실행해 다이제스트를 만들고 사람이 반영한다.

**영역별 초기 검토(현재 반영).** 대부분의 영상 도메인은 별도 인코더가 필요한 **멀티모달 확장** 항목이다
(현 텍스트 파일럿 범위와 구분).

| 도메인 | 대표 오픈모델/데이터 | 반영 경로 | 상태 |
|--------|----------------------|-----------|------|
| 영상의학 | RadFM(16M 2D/3D, 5000+ 질환), MedGemma·MedSigLIP, CheXagent | 멀티모달 확장(판독 근거) | watching |
| 병리 | UNI, Virchow, CONCH, Prov-GigaPath(WSI) | WSI 멀티모달 확장 | watching |
| 안과 | RETFound(안저/OCT) | 멀티모달 확장 | watching |
| 순환기 | ECG 딥러닝, echo AI | 신호/영상 확장(텍스트 지식은 반영) | evaluating |
| 소화기/내시경 | SurgFM·Surg-3M | 멀티모달 확장 | watching |
| 상병 코딩 | Agentic ICD-10 자동코딩 | 상병 태깅·정규화(icd_codes) | evaluating |
| 가이드라인 | 학회 가이드라인 | 공용 서고(출처) RAG | adopted |
| 술기 | SurgFM, 술기 평가 ML | 멀티모달 확장 | watching |
| 베이스 LLM | Meditron·MedGemma·Qwen/Llama·OpenBioLLM | 공유 베이스 후보 | evaluating |

## 7. 개인화와 개인 지식모델

Cerno의 개인화 대상은 "스타일"만이 아니라 **판단 흐름·맥락 반응**이다. 전문가의 **암묵지(tacit
knowledge)** 는 맥락 의존적·체화적이어서 규칙으로 전이되지 않고 실천-반성 순환으로 형성된다는 연구
(체화인지 모델)는, 개인 서고가 문서 나열이 아니라 **판단 근거·맥락**을 담아야 하고 human-in-the-loop이
편의가 아니라 **원리적 요구**임을 뒷받침한다. 따라서 증류 데이터는 단순 답변 쌍을 넘어 "왜 그렇게
판단했는가"(externalization)에 초점을 둔다.

**개인 지식모델의 3중 구조** — 개인 서고(RAG) + 개인 어댑터(LoRA) + (확장) 개인 지식그래프. 다수
의료진으로 확장할 때는 **Retrieval-Augmented Mixture of LoRA Experts(RAMoLE)** 처럼 어댑터를 검색·
라우팅하는 업로드형 개인화로 스케일하고, 개인 자료를 지식그래프로 구조화하는 방향(RECAP-KG류)을
검토한다. 봉합·박리 같은 **술기(procedural skill)** 는 수술 영상·키네매틱 기반의 별개 계열로, 현 텍스트
파일럿 범위 밖이며 멀티모달 확장 항목으로 둔다.

---

## 8. 안전과 거버넌스

Cerno는 진단·처방을 자동 확정하지 않는 **보조 도구**이며 human-in-the-loop을 전제한다.

- **근거·출처:** 모든 답변에 근거의 공개범위·출처를 표기. 근거 부족 시 단정하지 않고 회피.
  (강제 인용이 근거 적합도를 높이고, 큰 모델일수록 내부지식을 우선하며 응답이 장황할수록 미근거가
  는다는 실증에 맞춰 저온도·길이 제한도 둔다.)
- **고위험 플래그:** 용량·응급·금기·소아/임신 등은 사람 검토를 유도.
- **데이터 주권:** 임베딩·검색·학습·서빙 전 과정을 원내에서 수행, EMR 유래 데이터는 저장하지 않고
  질의 시점에만 사용. PHI는 비식별화 후에만 처리.
- **저작권·약관:** 프론티어 모델로 학습데이터 생성 시 약관·법무 검토를 통과한 경로만(코드에 명시적
  게이트). 공용 지식·데이터셋은 라이선스 확인 후 반영.
- **규제:** 영상 진단 모델 등은 의료기기(SaMD) 인허가 대상일 수 있어 반영 전 규제·법무 확인.

## 9. 관련 연구 (Related Work)

Cerno가 결합한 요소는 각각 성숙한 선행연구·제품이 뒷받침하며, 독자성은 **조합과 지식 거버넌스**에 있다.

- **오픈웨이트 의료 모델:** MEDITRON(EPFL·Yale, Llama 기반 7B/70B 완전 공개), MedGemma·MedSigLIP
  (Google, Gemma 3 기반 4B·27B, 로컬 파인튜닝·프라이버시 통제). → 베이스 후보. Cerno는 베이스를
  만들지 않고 그 위에 개인화·지식관리를 얹는다.
- **임상 RAG·출처 강제:** Citation-Enforced Prompting(강제 인용이 근거 적합도 최고, 내부지식 우선·
  장황함 경고), RAG in Healthcare 체계적 리뷰(정확도↑·환각↓, 그러나 표준 평가·윤리·프라이버시 공백).
  → Cerno의 출처·회피 가드레일과 평가·거버넌스 강조를 정당화.
- **의료진 개인화·암묵지:** 전문가급 임상 노트 생성 적응, LoRA 온프레미스 배포, 체화인지 암묵지 모델,
  RAMoLE(어댑터 검색·라우팅). 상업적으로 Dragon Copilot 등 의사별 노트 개인화가 검증됨.
- **도메인 파운데이션:** RadFM(영상의학), UNI·Virchow·Prov-GigaPath(병리), SurgFM(술기), ICD 자동코딩.
- **온프레미스 제품:** John Snow Labs Medical LLM 등. → "의료진별 개인화 + 개인/공용 지식의 계층적
  출처 관리"를 온프레미스로 묶은 조합은 여전히 뚜렷한 공백이며 Cerno가 겨냥한다.

(전체 참고문헌은 12장. 이전 개별 문서 03~06의 상세 검토를 본 백서로 통합했다.)

## 11. 평가

RAG 리뷰가 지적한 "표준 평가 부재"에 대응해, 파일럿은 다음을 **사전 정의된 정량 지표**로 평가한다:
근거 적합도(미근거 문장 비율 등)·인용 정확도·환각률, 개인화 적합도(해당 의료진 방식과의 유사도),
안전성(고위험 처리·근거 부족 시 회피·PHI 노출), 운영(지연·동시성). 임상 배포 전
**의료진 검수 + 소규모 섀도우 운영**을 둔다. 지연 목표 수치는 AI 서버 사양서 v2.0 §11에 위임한다.

**측정 프로토콜(필수).** 선행 사례에서 얻은 교훈 둘을 규율로 둔다.
- **표본이 불충분하면 확인이 아니다** — N=5 비교가 모델 비결정성을 놓쳐 배포 후 롤백된 사례가 있다. **N≥10**.
- **측정 전 워밍업 1회** — KV/프리픽스 캐시의 콜드·웜 차이가 비결정성으로 오인된다. 특히 on-demand
  서빙 환경에서 중요하다.

## 12. 용어 · 참고문헌 · 부록

### 용어
- **오픈웨이트(open-weight):** 가중치가 공개되어 온프레미스 자체 운영이 가능한 모델.
- **LoRA:** 소량 파라미터만 학습해 스타일·행동을 개인화하는 경량 미세조정.
- **RAG:** 질의 시 관련 문서를 검색해 근거로 제시하는 방식.
- **증류(distillation):** 프론티어 모델의 출력을 학습데이터로 삼아 소형 모델에 전이.
- **provenance:** 근거의 출처·저작권 등 유래 정보.
- **SaMD:** Software as a Medical Device(의료기기로서의 소프트웨어).
